# Documentation

The documentation has four parts, and each part has its own way of staying accurate.

| Part          | Location                  | Kept accurate by                                                       |
| ------------- | ------------------------- | ---------------------------------------------------------------------- |
| README        | `README.md`               | Kept short: what the package is, its requirements and its installation |
| Guides        | `docs/getting-started.md` | Their examples are type-checked files                                  |
| Concepts      | `docs/concepts/`          | Updated in the same pull request as the area they describe             |
| API reference | Generated from the source | TypeDoc fails the build for an undocumented export or a broken link    |

## Rules

- A pull request that changes the public API of an area updates the concept page of that area.
- Code in the documentation that uses the framework lives in `docs/examples/` as a TypeScript file. The examples are
  type-checked against the current source by `npm run typecheck`, so a change to the API that breaks an example fails
  the build.
- A page embeds an example with an `example` marker followed by an empty or outdated `ts` block. `npm run docs:sync`
  copies the file into the block, and `npm run docs:check` fails when a block differs from its file.
- `npm run docs:check` also fails for a relative link to a missing file or a missing heading, and for an export in
  `src` without a documentation comment, including exports that only other files of the same area use. TypeDoc checks
  only what the entry points export.

## The API reference

The API reference is generated by TypeDoc from the documentation comments. TypeDoc does not support TypeScript 7, so
it runs from `tools/typedoc` with its own TypeScript version. Install it once, then generate the reference into
`api-reference/`:

```shell
npm ci --prefix tools/typedoc
npm run docs:api
```

The reference is not committed and not published. CI generates it to check that every export is documented and every
link in a documentation comment resolves. Each CI run also uploads it as the `api-reference` artifact, kept for 14
days: open the run from the checks of a pull request and download the artifact from its summary page.
